# Better-EhViewer 修改说明

本仓库基于 [EhViewer-NekoInverter/EhViewer](https://github.com/EhViewer-NekoInverter/EhViewer) 1.8.14 修改（2026 年 11 月），
修改版本同样以 GNU GPL v3 发布，源代码即本仓库。

## 新增功能

两个功能都在 **设置 → EH** 末尾，默认关闭，彼此独立，设置保存在 SharedPreferences 中。
只作用于搜索结果和普通画廊列表（首页、订阅、热门、排行榜、标签/上传者/以图搜图结果），
**不影响** 收藏列表、下载列表和历史记录。

### 隐藏已收藏的画廊

* 只按画廊 ID（gid）匹配，从不根据标题判定收藏。
* 状态来源（优先级从高到低）：
  1. 本地收藏数据库（`eh.db` 的 `LOCAL_FAVORITES` 表）；
  2. 已登录时 E-Hentai 在列表页上为已收藏画廊画出的收藏色标（每次加载列表都是服务器最新状态）；
  3. 云端收藏缓存（独立数据库 `cloud_favorites.db`），来源包括：浏览云端收藏页、在应用内添加/移除/移动收藏，以及完整同步；
  4. 24 小时内的完整同步可以证明“未收藏”。
* 无法确定状态（未登录但有缓存、从未同步、同步失败、缓存与列表页冲突且无法证明登录有效）时为 **未知**：
  画廊保持显示，列表模式下显示半透明的心形图标，并提示一次可在设置中同步。
* 同步策略：只有在开启隐藏、已登录且列表中出现未知状态时才自动同步；完整同步每 24 小时最多一次，
  失败后 30 分钟内不重试；每次最多请求 100 页，页间隔 1.5 秒；可在设置中手动“同步云端收藏”。
  同步失败或中途停止时只会追加“已收藏”，不会删除缓存，也不会把任何画廊判定为未收藏。
* 收藏状态改变时，列表通过 DiffUtil 增量刷新，滚动位置保持不变。

### 折叠同一作品的不同版本

* 优先使用 E-Hentai 自身的版本链（gdata API 的 `parent_gid` / `first_gid`，详情页的 Parent 与 Newer versions）。
* 否则使用保守的启发式：规范化后的核心标题（罗马音标题或日文标题任一）**且** 至少一个相同的作者/社团
  （`artist:`/`group:` 标签或标题开头的 `[社团 (作者)]`）。
  另外要求分类相同、作者标签和原作标签不冲突、页数相差不大；`(前編)`/`(後編)`、`Ch. 1`/`Ch. 2` 等不会被合并；
  只有通用词的标题（如 “Artist CG Collection”）不参与折叠；没有作者信息的同名画廊不会被合并。
* 每组显示一个代表：优先“折叠后优先显示的语言”（默认跟随应用语言），再按质量（不完整、机翻、水印扣分；
  无修正、DL 版加分；评分、页数），最后取较新的上传。
* 代表画廊下方有“展开其他 N 个版本”入口，展开后可以正常打开任一版本。

### 分页与加载

* 原始分页数据不变，显示层做映射，因此翻页、跳页、下拉刷新、网格/列表切换照常工作，跨页重复的画廊会被去重。
* 当前页可见结果过少时自动加载下一页，但在没有用户操作（滚动、刷新、点按）的情况下最多连续自动请求 3 页；
  所有已加载结果都被隐藏时显示提示，点按后才继续加载。

## 安装与数据迁移

* CI 构建的是 `better` 构建类型：applicationId 为 `org.moedog.ehviewer.better`，应用名 “EhViewer Better”，
  版本名 `1.8.14-better`。它与原版 `org.moedog.ehviewer` **并存安装**，不会覆盖原版，也不会读写原版数据。
* 签名使用仓库中已有的 `app/keystore/androidkey.jks`，没有修改原版签名配置。因为包名不同，签名与原版无关。
* 迁移数据：在原版中 “设置 → 高级 → 导出数据”，在 EhViewer Better 中 “导入数据”（下载记录、历史、本地收藏、
  快速搜索、过滤器）；登录需要重新进行。导出文件格式未变（`eh.db` 版本仍为 4），可以双向导入。
* 云端收藏缓存是可以重新同步的派生数据，不包含在导出文件中。
