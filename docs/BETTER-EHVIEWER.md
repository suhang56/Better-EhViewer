# Better-EhViewer 修改说明

本仓库基于 [EhViewer-NekoInverter/EhViewer](https://github.com/EhViewer-NekoInverter/EhViewer) 1.8.14 修改（2026 年 11 月），
修改版本同样以 GNU GPL v3 发布，源代码即本仓库。

## 新增功能

两个功能都在 **设置 → EH** 末尾，默认关闭，彼此独立，设置保存在 SharedPreferences 中。
只作用于搜索结果和普通画廊列表（首页、订阅、热门、排行榜、标签/上传者/以图搜图结果），
**不影响** 收藏列表、下载列表和历史记录。

### 隐藏已收藏的画廊

* 只按画廊 ID（gid）匹配，从不根据标题判定收藏。
* 状态来源（优先级从高到低）：
  1. 本地收藏数据库（`eh.db` 的 `LOCAL_FAVORITES` 表）；
  2. 已登录时 E-Hentai 在列表页上为已收藏画廊画出的收藏色标（每次加载列表都是服务器最新状态）；
  3. 云端收藏缓存（独立数据库 `cloud_favorites.db`），来源包括：浏览云端收藏页、在应用内添加/移除/移动收藏，以及完整同步；
  4. 24 小时内的完整同步可以证明“未收藏”。
* 列表页“没有收藏色标”只有在能证明登录有效时才算“未收藏”：该页本身出现过收藏色标、ExHentai 页面，
  或本次会话 6 小时内成功加载过收藏页（Cookie 失效时 E-H 会返回游客页，同样没有色标）。
  缓存与列表页冲突时，以时间较新的一方为准。
* 无法确定状态（未登录但有缓存、从未同步、同步失败、无法证明登录有效）时为 **未知**：
  画廊保持显示，列表模式下显示半透明的心形图标；仍无法解决时提示一次可在设置中同步。
* 同步策略（只在开启隐藏、已登录、且列表中出现未知状态时自动进行，打开开关本身不会触发请求）：
  1. 若本次会话尚未验证登录，只请求 **1 页** 收藏页验证 Cookie 并补充缓存（失败后 30 分钟内不重试）；
  2. 仍有未知状态时才做完整同步：每 24 小时最多一次，失败 30 分钟后重试，因页数上限等原因不完整时 24 小时后重试；
     每次最多 100 页，页间隔 1.5 秒；也可在设置中手动“同步云端收藏”（同步进行中点按会等待并报告该次结果）。
* 同步失败或不完整时只追加“已收藏”，不删除缓存，也不会把任何画廊判定为未收藏；同步期间用户的添加/移除优先。
  退出登录会取消正在进行的同步并清空缓存，旧会话的同步结果会被丢弃。
* 收藏状态改变时，列表通过 DiffUtil 增量刷新，滚动位置保持不变。

### 折叠同一作品的不同版本

* 优先使用 E-Hentai 自身的版本链（gdata API 的 `parent_gid` / `first_gid`，详情页的 Parent 与 Newer versions）。
* 否则使用保守的启发式：规范化后的核心标题（罗马音标题或日文标题任一）**且** 至少一个相同的作者/社团
  （`artist:`/`group:` 标签，或标题开头最后一个 `[社团 (作者)]` 块；`[AI Generated]`、`[Unknown]`、汉化组等不算作者）。
  另外要求分类相同、作者标签/原作标签/展会（如 `(C95)` 与 `(C96)`）不冲突、页数相差不大。
* 标题末尾的 `[ ]` / `【】` 块只有在是语言、汉化组/译者署名（位于语言标记之后）、画质/版本/大小标记时才被忽略；
  其他块（`【前編】`、`[Part 2]`、`[第1話]`、`[2023-05]`、cosplay 的服装名等）都算作品身份，因此不会被合并。
  数字的分隔符会保留（`1.5` ≠ `15`，`1-3` ≠ `13`）；「」是普通引号；泰文等组合字符会保留。
* 只有通用词的标题（如 “Artist CG Collection”、“CG集”、“FANBOXまとめ”）不参与折叠；没有作者信息的同名画廊不会被合并。
* 每组显示一个代表：优先“折叠后优先显示的语言”（默认跟随应用语言），再按质量（不完整、机翻、水印扣分；
  无修正、DL 版加分；评分、页数），最后取较新的上传。
* 列表模式下代表画廊下方有“展开其他 N 个版本”入口；网格模式下为缩略图左下角的“+N 个版本”角标。
  展开后其他版本紧跟在代表之后，标注“同一作品的其他版本”，可以正常打开任一版本；展开状态在返回列表、旋转屏幕后保留。
* 代表画廊的选择：优先“折叠后优先显示的语言”；未列出的语言（印尼语、阿拉伯语等）不会被当成日语原版。

### 最少评分人数

* 设置 → EH →“最少评分人数”：关闭（默认）/ 5 / 10 / 20 / 50 / 100 / 200 / 500。
  E 站的“最低评分”只能按平均分筛，这里补上按评分人数筛。
* 限制：评分人数只出现在画廊详情页，列表的 5 种显示模式和 gdata 接口都没有（已在 CI 中抓取真实页面确认）。
  因此只能逐个读取详情页，为此做了这些限制：
  * 只查屏幕上的画廊，查完后再查其下方 4 个（由近到远）；已被收藏隐藏或被折叠收起的不查；
    离开列表、打开搜索面板、换新搜索或列表为空时立即停止；
  * 同时只查 1 个，间隔 ≥ 1.2 秒，每小时最多 300 次；出错或页面异常时逐步放慢（5 秒起，最长 10 分钟）；
    E 站提示“打开页面太快”时暂停 15 分钟，提示 IP 临时封禁时暂停 1 小时；这些限制在 App 重启后依然有效；
  * 结果永久保存在独立的 `gallery_stats.db`：评分人数只增不减，达标的永不再查；未达标的满 7 天后
    重新显示并在出现在屏幕上时重查（新上传的画廊人数会增长）；自己打开过或评过分的画廊直接记录，不额外请求。
* 折叠的同一作品中某个版本因人数不足被隐藏时，该组仍留在原位置，只是少了那个版本。
* 未查到的画廊先显示，查到人数不足时从列表中移除（不跳动、保持滚动位置）。

### 最少收藏次数 / 按收藏次数排序

* 设置 → EH →“最少收藏次数”：关闭（默认）/ 10 / 50 / 100 / 200 / 500 / 1000 / 2000；做法与“最少评分人数”相同。
* 设置 → EH →“按收藏次数排序”（默认关闭）：把**已加载**的结果按被收藏次数从多到少排列。
  E 站不支持按收藏次数排序，收藏次数同样只在详情页里有，所以：
  * 需要读取所有已加载画廊的详情页（屏幕上的优先），限速与上面相同（每个约 1.2 秒，一页 25 个约 30 秒），
    开始时提示预计时间；
  * **全部读取完成后一次性排序**，期间保持原顺序，不会边查边跳；之后加载的新一页先排在末尾，读取完成后再整体重排；
  * 折叠的同一作品按显示的代表版本排序，展开的其他版本跟随一起移动。
* 评分人数和收藏次数来自**同一个详情页**，几个功能同时开启也只请求一次；结果一起缓存，收藏次数满 30 天后排序时会刷新。

### 分页与加载

* 原始分页数据不变，显示层做映射，因此翻页、跳页、下拉刷新、网格/列表切换照常工作，跨页重复的画廊会被去重。
* 当前页可见结果过少时自动加载下一页，但在没有用户操作（滚动、刷新、点按、上滑）的情况下最多连续自动请求 3 页；
  之后若列表短到无法滚动，在列表上 **上滑** 即可继续加载（会提示一次）；所有已加载结果都被隐藏时显示提示，点按后才继续加载。
  该提示不会覆盖加载中、出错或“无结果”的提示。

## 安装与数据迁移

* CI 构建的是 `better` 构建类型：applicationId 为 `org.moedog.ehviewer.better`，应用名 “EhViewer Better”，
  版本名 `1.8.14-better`。它与原版 `org.moedog.ehviewer` **并存安装**，不会覆盖原版，也不会读写原版数据。
* 签名使用仓库中已有的 `app/keystore/androidkey.jks`，没有修改原版签名配置。因为包名不同，签名与原版无关。
* 迁移数据：在原版中 “设置 → 高级 → 导出数据”，在 EhViewer Better 中 “导入数据”（下载记录、历史、本地收藏、
  快速搜索、过滤器）；登录需要重新进行。导出文件格式未变（`eh.db` 版本仍为 4），可以双向导入。
* 云端收藏缓存是可以重新同步的派生数据，不包含在导出文件中。

## 测试

纯逻辑代码位于 `app/src/main/java/com/hippo/ehviewer/gallerylist/`，单元测试位于 `app/src/test/`
（含 20 个“不得误合并”的对抗用例：前编/后编、[Part 2]、1.5 与 15、不同展会、[AI Generated] 等）：

```
./gradlew :app:testDebugUnitTest
```

设备端验证位于 `app/src/androidTest/`，由 `.github/workflows/verify.yml` 在 API 34 模拟器上、
以游客身份访问 **真实的 e-hentai.org** 运行（`./gradlew :app:connectedDebugAndroidTest`）：

* 真实搜索页的解析与折叠（逐组输出成员、语言、代表），以及跨页去重；
* gdata API 的 `parent_gid` / `first_gid` 字段与详情页 Parent / Newer versions 的一致性，以及版本链登记；
* 云端收藏缓存在 Room 中的增删改、完整/不完整/失败同步、4 万行批量；
* 列表页收藏色标解析（在真实页面上注入 E-H 的收藏样式）；
* 评分人数读取与详情页解析一致；界面中按评分人数隐藏：只查附近的画廊、间隔 ≥ 1 秒、不重复查、
  离开列表即停止、关闭后全部恢复；
* 真实界面端到端：展开 →“同一作品的其他版本” → 打开其中一个版本 → 返回后仍展开且滚动位置不变 → 收起；
  收藏后就地隐藏且列表不跳动、取消收藏后回到原位置；滚动分页无重复；网格模式角标；
  前 4 页全部已收藏时请求数有上限（1 + 3）、空闲时不再请求、点按提示后继续加载且不重复请求同一页。

未覆盖：需要登录的部分（真实云端收藏页、ExHentai）无法在 CI 中以游客身份验证，
相应逻辑由单元测试与注入色标的设备测试覆盖。
